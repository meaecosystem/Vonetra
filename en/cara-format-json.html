How to Clean Up and Validate Messy JSON

JSON from an API response or a log often comes as one long line that's nearly impossible to read with the naked eye. Here's how to tidy it into a readable structure, and check for a typo breaking the syntax while you're at it.

If the JSON errors out, where's the problem?

The most common causes of a failed JSON parse are a trailing comma at the end of an array or object, inconsistent quotes (it must be double quotes, not single quotes), or unbalanced brackets. If the input you pasted isn't valid, this tool will tell you exactly where the error is, so you don't have to comb through it manually.

Format vs. minify — when should you use which?

Format (tidy up) is best when you're reading or debugging data — the nested structure becomes clearly visible. Minify (collapse) is better when the JSON is going somewhere that cares about small file size, like a production config file or an API payload.

Frequently asked questions

Is the JSON I paste sent to a server?

No. All parsing, formatting, and validation runs directly in your browser.

Is there a size limit on the JSON that can be processed?

There's no limit from the service side. The only limit is your browser's and device's capability for very large JSON.

What's the difference between valid JSON and JSON that just "looks right"?

Valid JSON follows strict syntax rules — double quotes are mandatory, trailing commas aren't allowed. This tool validates against that standard, so anything that "looks right" but is actually wrong will still be caught.
